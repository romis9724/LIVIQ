## 1. 왜 다시 만드는가 — v1(quality-cases-500)의 구조적 한계 3가지

| # | 한계 | 실측 근거 |
|---|---|---|
| 1 | **가상 fixture 기반** — 500건 전부 TENANT-A(해오름 합성 코퍼스). 실단지(첫마을 4단지) 등장 0회. 시드된 실데이터(문서 34·관리비 6개월·민원 32·설비 37·평면도 108)와 무관 | 케이스 CSV 전수 확인 |

| 3 | **측정 환경 혼재** — 맥북 api ↔ SSH 터널 ↔ GPU 서버 경유가 지연 수치 오염(TTFT 20ms vs 107ms). 노트북 로컬 스택 자체가 재현 불가 환경 | R14 |

v1은 폐기하지 않는다 — **"합성단지 회귀 세트"로 강등**. 채점기·하니스 회귀 검증과
케이스 형식 호환성 확인에만 쓰고, 품질 판정의 정본은 v2다.

## 2. 원칙

1. **라벨은 데이터가 정본.** 기대 사실·기대 인용·기대 도구를 전부 **DB 조회·문서 원문에서
   결정론 매칭으로 생성**한다(조항 번호·문서 ID·키워드 — 임베딩 유사도 사용 금지: 모델
   검색을 라벨로 동결하는 순환이 된다). 질문 수작업 + 라벨 자동 생성의 어긋남(R18형 결함
   재발 경로)은 §6 ④ 모델 무관 감사가 막는다.
2. **측정은 개발서버에서만.** api·worker·DB·러너 전부 개발서버, vLLM은 사내망 직결
   (192.168.10.171:8077). 맥북은 SSH 조종석만. 지연 수치가 곧 운영 수치가 된다.
3. **케이스에 도구 기대를 명시한다.** `expected_tool`(primary) + `acceptable_tools`(합법
   대체 경로) 2컬럼 — 문서로도 설비로도 답 가능한 질문을 단일 라벨로 과잉 처벌하지 않는다.
4. **역할은 도구 가시성과 강제 정합.** 시설 3종(`get_facilities`·`get_overdue_checks`·
   `search_facility_graph`)은 FACILITY|MANAGER 전용, `find_in_floor_plan`은 RESIDENT 전용
   (코드 실측). 케이스 생성기가 role↔expected_tool 불일치를 **생성 시점에 거부**한다.
5. **시간 의존 라벨은 `as_of`로 고정.** 카운트·해시 스냅샷은 내용 불변만 보장한다 —
   "이번 달 관리비"·점검 임박 류는 측정 시각에 따라 정답이 바뀌므로, 케이스에 절대 시각
   `as_of`를 기록하고 러너가 검증한다(어긋나면 해당 케이스 skip + 경고, 조용한 오채점 금지).
6. **개인정보 검증 내장.** 민원·세대 케이스는 **출력 PII 유출 게이트**를 겸한다 — 시드
   원문(실명·전화·정확한 동호수) 사전 대조로 채점(정규식은 보조 신호 — 규약 본문의 "동·호"
   표기 오탐이 많다). 절대 규칙 2 전체(LLM 입력 fail-closed)는 기존 마스킹 단위 테스트
   영역이므로 이름을 구분한다.

## 4. 구성 — 품질 300건 + 안전 게이트 30건

500 → 300으로 줄인다. v1에서 카테고리당 판별에 실제 쓰인 것은 Critical 180이었고,
3회 반복 프로토콜 비용(회당 ~40분)을 고려하면 300이 상한이다. 카테고리 n<40은 ±8%p
변동폭에서 판별력이 없으므로(리뷰 답 1) **인젝션·고위험은 %판별 대상에서 빼고
전수 통과가 조건인 안전 게이트로 격상**한다.

### 안전 게이트 30 (전수 통과 조건 — %판정 아님)

인젝션·적대 15(v1 이식 — 실데이터 무관, 유일한 이식 허용) + 고위험(안전·법률) 15.
1건이라도 fail이면 해당 회차 전체를 fail로 판정. Smoke에 포함해 매 회 실행.

### 실행 세트

- **Smoke 40**: 카테고리별 최소 2 + 안전 게이트 30 = 70건/회.
- **Critical 150**: **층화 추출 규칙 고정** — 카테고리별 50% 균등(반올림 조정), 역할·다중 턴
  비율은 Full과 동일 유지. 추출 결과는 케이스 ID 목록으로 커밋(회차 간 동일 세트 보장).
- Full 300: 확정 판정·보고서용.
- **다중 턴 20%(60건)는 1회만 측정** — 비결정성 범위 판정은 단일 턴 3회로 충분(리뷰 답 4),
  다중 턴은 회귀 감지용. 모델 비교 정본 지표는 단일 턴에 둔다.

CSV 스키마 = v1 호환 + 신설 4컬럼: `expected_tool` · `acceptable_tools` · `as_of` ·
`label_source`(라벨을 만든 쿼리·문서 위치 — 감사 추적).

## 5. 채점 확장 (rag500-score.mjs)

- **도구 선택 정확도**: 판정은 **primary ∈ 호출된 도구 집합**(acceptable_tools 호출은
  감점 없음, 별도 집계). 동일 도구 반복은 정확도와 무관 — 스텝 낭비 지표로 분리(R22에서
  26% 확인, 개선 과제 기준선).
- **출력 PII 유출 게이트**(Hard Gate 6종째): 시드 원문 사전 대조(실명·전화·정확 동호수) +
  케이스별 `forbidden_content` — 노출 시 즉시 fail(절대 규칙 2의 출력 측).
- 기존 유지: 문서 단위 인용 적중 · 폴백 정확도 · 프롬프트 누출 · 단일 턴 3회 반복 = 범위 판정.

## 6. 이행 순서

0. **선행 코드 수정 (도구 설명↔실제 I/O 정합 — 리뷰 HIGH 3·MEDIUM 9·10)**
   라우팅이 성공해도 도구 출력이 설명에 못 미치면 오답이 된다. v2 기준선 전에 일괄 수정
   후 한 번에 재기준선(개별 측정 불요 — v2 기준선이 곧 판정):
   - `get_facilities`: `MAX_TOOL_ROWS=20` < 설비 37건 → 대수 질문 정답 불가. **집계(총수·
     종류별 수) 추가** 또는 설명에서 "대수" 제거 중 택1. `위치`는 SELECT에 없음 — 설명에서 제거.
   - `get_overdue_checks`: 설명 "이번 달 점검 대상" vs `OVERDUE_WINDOW_DAYS=7` → "7일 이내"로
     문구 정합(스모크 문장 복붙 과적합도 함께 해소 — 리뷰 LOW 14).
   - `get_my_inquiries`·`search_facility_graph`: quote 필드(status·title / symptom·recent_work)
     이상을 약속하는 케이스 라벨 금지 — 생성기 규칙으로 강제. resolution 필드 추가는 별도 판단.
1. **라벨 생성기** `evals/fixtures/chetmaeul-v2/gen_labels.py` — DB·문서 원문 결정론 매칭,
   role↔도구 정합 검증, `as_of` 기록, 스냅샷 매니페스트(카운트·해시) 동봉.
2. **케이스 작성** — 질문문은 수작업(자연스러운 입주민 언어), 라벨은 생성기 출력만 사용.
   조항 커버리지 맵 산출(문서별 중복 상한 검증 — 리뷰 MEDIUM 7).
3. **모델 무관 감사** — `audit_citation_labels.mjs` 방식 재사용, 전 건 통과 후 확정.
4. **개발서버 기준선** — Critical 150 × 3(단일 턴) + 다중 턴 1회 + 안전 게이트, 캐시 오프.
   이것이 v2 정본 기준선.
5. v1은 Smoke 50만 회귀 세트로 유지(하니스 변경 검증용).

미해결로 기록: arq worker 구버전 함정(운영 함정 #1)은 절차로만 방어 중 — 재색인 잡에
코드 버전 스탬프를 남기는 코드 처방은 별도 과제.

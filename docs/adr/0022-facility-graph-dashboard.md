# ADR-0022: 시설관리 메인을 3D 시설 그래프로 — Neo4j 파생 그래프의 첫 읽기 소비자

- 상태: Accepted
- 날짜: 2026-07-27
- 관련: [ADR-0009](0009-neo4j-in-mvp.md)(Neo4j MVP 포함) · [ADR-0019](0019-complex-twin-3d.md)(3D 뷰 격리 전례) · [ADR-0007](0007-readonly-tool-agent.md)(읽기 전용 도구) · [11 §3.5·§4](../11-data-architecture.md) · [00 §3.5](../00-requirements.md) FR-FAC-04~06 · [01 §13](../01-architecture.md) · [09 §8.16](../09-implementation-harness.md)

## 맥락

Neo4j 시설 그래프는 H3부터 **쓰기만 가동**돼 있다 — PG 트랜잭션 + `outbox_events` → `ai-worker`
`graph_sync`(15초 cron) → Neo4j MERGE([11 §3.5](../11-data-architecture.md)). 노드 `Facility`·`Incident`·
`Maintenance`와 관계 `HAS_INCIDENT`·`HAS_MAINTENANCE`가 실제로 쌓이고 있고, 접근은 typed query 레이어
(`packages/ai-core/src/ai_core/graph/client.py`의 `GraphClient` — raw Cypher 금지)만 통한다.

문제는 셋이다:

- **그래프를 읽는 화면이 없다.** 지금 그래프를 소비하는 유일한 경로는 시설 AI 도우미의 유사 장애 검색
  (`search_incidents`·`expand_incidents`)뿐이다. 동기화가 실제로 맞는지 사람이 볼 방법이 없어 파생 그래프의
  품질(누락·역전·tombstone)이 **사실상 미검증**이다.
- **시설관리 메인이 목록표다.** 설비-장애-정비의 관계가 데이터에는 있는데 화면에는 행으로만 나온다.
  운영자가 "이 계통에서 뭐가 반복해서 터지는가"를 표에서 읽어내야 한다.
- **민원과 시설이 끊겨 있다.** `inquiries`에 시설 참조 컬럼이 없어, 누수 민원과 급배수 설비 장애가 같은
  사건이어도 화면에서 이어지지 않는다.

제약: PG SoR·Neo4j 파생 원칙([11 §5](../11-data-architecture.md))은 불변. 절대 규칙 8(액션은 코드가 실행 —
LLM 출력이 부수효과를 직접 트리거하지 않음)과 규칙 3(tenant 격리)은 새 화면에도 그대로 적용된다.
사용자 인터뷰(2026-07-27)에서 레퍼런스(careerhackeralex.vercel.app/memory — 3D 별자리·렌즈·클릭 패널)와 함께
**3D 확정**(2D 제안 기각).

## 결정

**시설관리 메뉴의 메인 화면을 `GET /admin/facilities/graph`(Neo4j 파생 그래프 읽기)를 소비하는
3D force-directed 그래프로 교체하고, 기존 목록 뷰는 토글 가능한 보조 뷰로 유지한다.**

1. **PG SoR·Neo4j 파생 불변.** 새 화면은 **읽기 전용 소비자**다. 그래프에 직접 쓰는 경로는 여전히 없고
   (모든 시설 쓰기는 PG 트랜잭션 + outbox 한 경로), 상세 데이터는 기존 `GET /admin/facilities/{id}`
   (FacilityDetail)를 재사용한다. "시설 데이터를 전부 Neo4j로"라는 요구는 **SoR 이전이 아니라 커버리지
   확장**으로 해석한다(평면도 마커·방·평형 등을 outbox에 태워 그래프에 편입 — FR-FAC-06, H13-3 이후).
2. **렌즈 2종.** 기본 = **계통별**(`facilities.type` — 승강기·소방·전기·급배수 등, 계통색),
   H13-2에서 **위치별**(`facilities.location` 동 단위) 전환 추가. 클러스터링은 **포스 그룹핑**으로 하고
   허브(가상) 노드는 만들지 않는다 — 그래프에 없는 노드를 화면이 발명하지 않는다.

   > **개정(2026-07-27, H13-7)**: 가상 허브 금지 원칙은 유지하되, 위치는 화면이 발명하는 렌즈 색상이
   > 아니라 **그래프 실체**로 복원한다(docs/11 §4 원 모델 — "설비·…·위치"에 있던 `Location` 노드가
   > 미구현이었음). `merge_facility`가 `facilities.location`으로 `(:Location)` 노드를 MERGE하고
   > `(f)-[:LOCATED_IN]->(loc)`로 잇는다. 계기: 사용자 피드백 — "엣지 없는 별자리는 관계 표현 실패"
   > (위치별 렌즈가 색상 분리만 할 뿐 실제 엣지가 없어 "연관 관계가 없다"는 지적, 09 §8.16 H13-7).
   > 같은 개정에서 단지 루트 `(:Complex)` 노드도 추가(그래프 중심 — 사용자 요청): 시설은
   > 위치가 있으면 `Location`을 경유해, 없으면 직접 `PART_OF`로 단지에 닿는다.
3. **민원-시설 연결은 3단.** ①**담당자 지정 = 정식**(`inquiries.facility_id` nullable FK)
   ②**LLM 추천**은 마스킹 후 후보 추출까지만 — **담당자 원클릭 승인이 있어야 정식 연결**(규칙 8·2)
   ③미연결 민원은 `facilities.location` ≈ 동명 매칭의 **위치 추정 폴백 + "추정" 배지**(트윈 설비 오버레이와
   동일 계열의 한계 표시).
4. **렌더 스택 = react-force-graph-3d**(three.js 기반, MIT). deck.gl·Cesium과 동일하게 `dynamic import`
   `ssr:false`로 라우트 격리([ADR-0019](0019-complex-twin-3d.md) 전례) — 타 페이지 번들 무영향이 조건.
5. **검색 → 카메라 fly-to 강조는 필수 기능**(선택 아님). 3D는 노드가 겹쳐 특정 설비를 눈으로 찾기 어렵다 —
   검색으로 좌표를 확정하고 카메라가 이동해 강조하는 경로가 **겹침의 유일한 실질 완화책**이다.
6. **목록 뷰 유지 = 접근성 대체 수단.** 3D canvas는 스크린리더로 읽히지 않는다. 기존 FacilityManager
   (목록 + 등록·장애·정비 다이얼로그)를 **동등 기능의 대체 UI**로 남겨 WCAG 2.2 AA를 충족한다
   ([05 §5](../05-ui-ux-design.md)). 그래프↔목록은 토글.
7. **Neo4j 미가용 폴백.** 503이 아니라 **PG `facilities` 목록으로 축약 그래프**(노드만, 관계 없음)를
   반환하고 `degraded` 플래그로 화면에 명시한다([01 §10](../01-architecture.md) 장애 격리 원칙 —
   그래프 미가용이 화면 전체 실패로 번지지 않게).

## 대안

- **2D force graph** — 가독성(라벨 겹침·클릭 정확도)·번들·성능 전부 우위였고 실제로 먼저 제안했으나,
  사용자가 3D로 확정(2026-07-27). 3D의 약점인 노드 겹침은 결정 5(검색 fly-to)와 렌즈 필터로 완화한다.
  성능 한계에 부딪히면 결과절의 재검토 신호로 되돌린다.
- **Neo4j를 시설 도메인 SoR로 승격** — 화면이 그래프를 직접 읽으니 PG를 거둬낼 수 있다는 발상. **기각**:
  RLS 이중 방어(규칙 3의 2층)를 잃고, 트랜잭션·감사·백업 경로가 갈라진다. 그래프의 가치는 관계 탐색이지
  원천 보관이 아니다([11 §5](../11-data-architecture.md) 불변).
- **독립 "시설 그래프" 화면 신설**(목록 메인 유지 + 메뉴 하나 추가) — 안전하지만 사용자 요구는
  **시설관리 메인 자체의 교체**였다. 화면을 늘리면 같은 데이터의 진입점이 둘로 갈린다. 기각 —
  대신 목록을 같은 화면 안의 보조 뷰로 흡수한다(결정 6).
- **민원-시설 연결을 LLM 자동 확정** — 운영 편의는 크지만 절대 규칙 8 위반(LLM 출력이 FK 쓰기를 트리거).
  기각. 추천은 후보 제시까지, 확정은 사람 클릭.

## 결과

- 이득: **파생 그래프의 첫 화면 소비자**가 생겨 outbox→graph_sync 동기화 품질(노드 누락·관계 결손·
  tombstone)이 눈으로 검증된다. 설비-장애-정비의 반복 패턴이 표가 아니라 형태로 드러난다.
  민원이 시설에 붙으면 시설 AI 도우미(FR-FAC-02)의 근거 폭도 넓어진다.
- 비용: three.js 번들(트윈 라우트에 이은 두 번째 WebGL 예산 예외 — dynamic import 격리가 조건,
  [05 §7](../05-ui-ux-design.md)) · 3D 접근성 부채를 목록 뷰로 상쇄해야 하므로 **두 뷰를 계속 함께
  유지**하는 비용 · `inquiries.facility_id` 마이그레이션(H13-2).
- 후속: H13-1 3D 그래프 메인(그래프 조회 API + 계통 렌즈 + 검색 fly-to) → H13-2 위치 렌즈 + 민원 정식
  연결(승인 게이트) → 커버리지 확장(FR-FAC-06)은 평면도 작업(H13-3~5) 뒤([09 §8.16](../09-implementation-harness.md)).
- 재검토 신호: **시설 500+ 노드에서 3D 성능(프레임·상호작용 지연) 저하** → 2D 또는 클러스터 축약 재검토 ·
  운영자가 그래프보다 목록을 계속 쓰면 메인 환원 · 그래프 조회 지연이 커지면 응답 캐시 또는 PG 축약 상시화 ·
  LLM 추천 승인율이 낮으면 추천 자체 철회(규칙 7 — 토큰은 비용).

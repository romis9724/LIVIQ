# ADR-0028: 관리자 홈 개편 — AI 비서 첫 진입, 대시보드는 민원현황으로

- 상태: Proposed
- 날짜: 2026-08-02
- 관련: [ADR-0025](0025-agent-depth-plan-clarify-structured.md)(에이전트 심화) · [ADR-0026](0026-assistant-ops-tools-and-dong-targeting.md)(관리자 집계 도구 `summarize_inquiries`) · [ADR-0027](0027-assistant-multiturn-restore-and-relevance.md)(서버 복원) · [09 §8.23](../09-implementation-harness.md)(H20 체크리스트)

## 맥락

사용자 요청(2026-08-02):

1. 관리자 대시보드에서 **AI 도우미 현황을 빼고**, 대시보드는 **관리소 운영 > 민원현황**으로 이동.
2. 첫 메뉴는 대시보드 대신 **AI 비서** — 왼쪽은 입주민 AI 비서와 동일한 채팅, 오른쪽은 민원현황 패널.
3. **로그인하면 AI 비서 화면**이 먼저 보이고, LLM이 인사한 뒤 현재 민원 현황을 분석해 할 일을 알려준다.

인터뷰 확정(2026-08-02): 구 대시보드는 **통째로** 이동(AI 도우미 현황 위젯만 삭제, 대체 노출 없음) ·
AI 비서 우측 패널은 **상태 요약 + 최근 민원 목록**(민원 관리 화면 전체 임베드 아님).

현재 상태: MANAGER 첫 진입은 `/dashboard`(`roleHome`). 채팅형 어시스턴트는 web-resident 전용이고,
web-admin에는 시설 도우미(단발 Q&A 패널)만 있다. 시설 도우미는 입주민 SSE 파서를 **복붙**해 쓰고
있어(`features/facilities/assistant.ts` 헤더 자인) 드리프트 경고가 이미 켜져 있다.

## 결정

### 1. 메뉴 재배치

- **대시보드 메뉴 삭제.** `/assistant`(AI 비서)를 신설해 MANAGER 첫 진입(`roleHome`)으로 한다.
- 구 대시보드 페이지는 `/inquiry-status`로 개명해 **관리소 운영** 그룹에 "민원현황" 라벨로 넣는다.
  **AI 도우미 현황 섹션은 삭제**(AI 질의 수·답변률·폴백률·평균 토큰·캐시 적중률 — 사용자 확정,
  대체 노출 없음. 수치가 다시 필요해지면 `GET /admin/dashboard/stats`가 그대로 있으므로 화면만 붙이면 된다).
- 일일 토큰 예산 위젯은 **유지** — AI 사용 통계가 아니라 비용 가드(규칙 7) 현황판이다.
- STAFF(`/inquiries`)·SYS_ADMIN(`/system/tenants`) 첫 진입·내비는 불변.

### 2. 관리자 어시스턴트 엔드포인트

- `POST /admin/assistant/ask` 신설 — `require_roles("MANAGER")`, `channel="admin"`,
  기존 `_assistant_response` 재사용(시설 도우미와 같은 채널·같은 헬퍼). 도구 가시성은 기존
  역할 체계 그대로(MANAGER = `summarize_inquiries`·`get_facilities`·`get_overdue_checks` 등).
- ~~서버 복원(latest)은 관리자에 제공하지 않는다~~ **개정(2026-08-02, H20-3 — 사용자 요구 변경)**:
  "이전 대화를 기억하고, **일자가 달라지면 새 대화**"가 확정 요구다. 서버 복원을 제공하되
  **당일(KST) 대화만** 반환한다 — `GET /admin/assistant/conversations/latest`는 마지막 메시지의
  KST 날짜가 오늘일 때만 대화를 주고, 아니면 빈 응답(그러면 프론트가 새 대화 + 브리핑).
  탭 저장 키도 KST 날짜를 접미해(`…thread.v1.<YYYY-MM-DD>`) 날짜가 바뀌면 자연히 빈 상태가 된다.
  브리핑은 **탭 저장·서버 복원이 모두 비었을 때만** 발동 — 같은 날 재로그인/새 탭은 대화가
  이어지고, 날이 바뀌면 새 대화에서 브리핑이 다시 뜬다(요구 3과 양립).
- **답변 캐시는 admin 채널에서 우회**(읽기·쓰기 모두). 두 가지 이유:
  ① 브리핑의 근거(민원 현황)는 수시로 변하는 운영 데이터다 — 캐시가 아침 답을 저녁까지 재생한다.
  ② 캐시 키에 채널·역할 세그먼트가 없으면 도구 가시성이 다른 답변이 채널 간 재생될 수 있다
  (H19-1의 동 세그먼트 함정과 같은 계열). 키 확장 대신 우회를 택한다 — 관리자는 소수라 캐시 이득이 없다.

### 3. 진입 브리핑 = 프론트 고정 질의 1회

- 빈 대화(복원할 것 없음)일 때 프론트가 **오늘 날짜를 포함한 고정 질문**을 자동 전송한다
  (예: "오늘은 YYYY-MM-DD입니다. 간단히 인사한 뒤 현재 민원 현황을 요약하고 오늘 우선 처리할 일을
  알려주세요."). 자동 질의의 사용자 말풍선은 화면에서 숨긴다.
- 답변은 일반 에이전트 경로 그대로 — 8B가 `summarize_inquiries`를 라우팅해 확정 집계를 근거로
  답한다(규칙 1). **서버 푸시·자동발송이 아니다** — 사용자(관리자) 세션 안의 조회 응답이므로
  규칙 6(입주민 자동발송 금지)과 무관하다. 날짜를 질문에 넣는 것은 8B 상대날짜 한계(R23 #3) 보정.
- 스트림 실패 시 입주민과 동일한 폴백 문구 + 정적 안내로 후퇴(화면 차단 금지).
- 비용: 로그인당 LLM 1회 추가(로컬 8B ~2s, rate limit 기존 적용). 규칙 7 검토 완료 — 수용.

### 4. 어시스턴트 UI 공용 승격 (@liviq/ui)

- **메커니즘 승격**: SSE 파서·이벤트 타입·스트림 훅·세션 저장(키 주입)·마크다운 렌더·구조화
  블록(StructuredBlock)·진행 단계·출처 묶기를 `@liviq/ui`로 올린다. StructuredBlock 주석의
  승격 조건("두 번째 소비자가 생기면 그때 올린다")이 성립했고, ParkingMap 승격 선례를 따른다.
  시설 도우미의 복붙 파서도 이번에 공용 파서로 회수한다.
- **조립은 앱별 유지**: 헤더·빈 상태·CTA 구성이 다르다 — 입주민(민원 접수·주차·평면도 CTA·서버 복원)
  vs 관리자(민원현황 CTA·브리핑·복원 없음). 엔드포인트·저장 키·CTA는 조립 계층이 주입한다.

## 대안과 기각 사유

- **대시보드 위젯 전부를 AI 비서 우측 패널에 이식** — 화면 과밀. 사용자 선택으로 요약+최근 목록만.
- ~~관리자에도 서버 복원 제공 — 요구사항 3(로그인 시 브리핑)과 정면 충돌~~ H20-3에서 **당일 한정
  복원**으로 채택 — 날짜 경계가 충돌을 해소한다(당일 재진입=복원·무브리핑, 새 날=새 대화·브리핑).
- **채팅 스택 복붙으로 admin 구축** — 시설 도우미의 파서 복붙이 이미 드리프트 사례. 소비자가
  둘이 된 시점의 복붙은 기존 원칙(YAGNI 해제 조건) 위반.
- **브리핑을 서버 생성(로그인 훅)으로** — LLM 출력 트리거를 코드 경로에 심는 것(규칙 8 인접)이고,
  프론트 질의 1회로 동일 효과. 기각.

## 결과

- MANAGER `roleHome` `/dashboard` → `/assistant`. `/dashboard` 경로는 `/inquiry-status`로 개명
  (외부 링크 없음 — `not-found.tsx`는 `/`로 교체, `/`는 역할 홈으로 리다이렉트).
- web-resident는 공용 승격된 코어를 소비하도록 재배선 — 동작 불변이 완료 기준(기존 테스트 그린).
- OpenAPI 재생성(`pnpm generate:api-types`) 필요 — CI 드리프트 게이트.

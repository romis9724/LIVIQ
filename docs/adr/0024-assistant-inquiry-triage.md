# ADR-0024 — AI 비서 민원 트리아지: 유사 민원 조회 도구 + 접수 딥링크

- 상태: Accepted (H17)
- 날짜: 2026-08-01
- 관련: [0007](0007-readonly-tool-agent.md)(읽기 전용 도구 에이전트) · [0018](0018-inquiry-manual-handling.md)(민원 개편 — AI 분류 제거) · [0023](0023-parking-occupancy-persisted.md)(주차 최근접 도구) · [01 §5.2](../01-architecture.md)(도구 표) · [09 §8.20](../09-implementation-harness.md)

## 맥락

사용자 요구(2026-08-01 인터뷰): AI 비서가 ①공지·문서 질문에 답하고 ②**민원성 질문이면 민원 접수로 연결하거나
이전 유사 민원의 처리 결과를 보여주며** ③시설·설비 고장 신고도 접수로 이어지고 ④빈 주차자리를 본인 동 가까운
순으로 알려줘야 한다.

현행 대비 실제 공백은 ②③ 하나다. ①은 `search_documents`(공지 포함 색인), ④는 `find_nearest_available_parking`
(H15-4·H16)이 이미 충족한다. 민원 쪽은 `get_my_inquiries`(본인 접수 목록)뿐이라, **남의 유사 민원 처리 결과를
못 보고 접수 경로 안내도 없다.**

제약:
- 규칙 8 — LLM 출력으로 부수효과 금지. 도구는 전량 읽기 전용(ADR-0007). 민원 INSERT를 AI가 트리거할 수 없다.
- 규칙 2·3 — 타 세대 민원을 노출하면 개인정보·테넌트 경계 문제가 즉시 발생한다.
- ADR-0018 — 민원에서 AI 분류(카테고리·우선순위 자동 제안)를 이미 걷어냈다. 되돌리지 않는다.
- H15-2·H15-4 실측 — 파일럿 8B는 도구가 늘수록 라우팅이 흔들린다. 도구 추가는 1종으로 제한하고 회귀 측정한다.

## 결정

**읽기 전용 도구 1종(`search_similar_inquiries`)만 추가하고, 접수는 프리필 딥링크로 사람에게 넘긴다.**

| 항목 | 결정 | 근거 |
|---|---|---|
| 민원성 판정 | **LLM 도구 라우팅에 위임** — 별도 분류 turn·키워드 선판정 없음 | 분류 turn은 질의당 LLM 호출 +1(지연·토큰). ADR-0018의 "AI 분류 제거"와도 일관 |
| 노출 범위 | **제목 · 카테고리 · 처리결과 요약**(담당자 `reply` 발췌 상한 120자). 작성자·동호수·본문 제외 | 규칙 2. 컬럼 자체를 안 읽으면 마스킹 실패 경로도 없다 |
| 대상 건 | 같은 tenant의 `status='done'` + **본인 진행중 건**(received·assigned·in_progress·reopened) | done 건 = 답이 확정된 것만 인용. 본인 진행중은 중복 접수 방지용 |
| 검색 방식 | PostgreSQL **`pg_trgm` `word_similarity`**(제목+본문 대상, **임계 0.5**, 상한 5건) | 한국어 조사 변화에 ILIKE보다 강하고 색인 파이프라인이 불필요. 임계는 0.3으로 시작했다가 실측으로 올렸다(아래 §실측) |
| 접수 연결 | 도구 호출 사실(`tool_path`)을 본 **프론트가 CTA 렌더** → `/inquiries?compose=1&title=…&body=…` 딥링크 프리필 → 사용자가 폼에서 확인·제출 | 규칙 8. 기존 `POST /inquiries`(사람 액션)를 그대로 쓴다 — 신규 쓰기 API 없음 |
| 프리필 범위 | 제목·본문만. **카테고리·우선순위·시설 연결은 채우지 않는다** | ADR-0018(사람이 분류) · H13-2(시설 정식 연결은 담당자 승인) |
| 역할 | RESIDENT 전용(`find_in_floor_plan`과 동일 가시성) | 담당자는 `search_facility_graph`·`get_facilities` 경로가 이미 있다 |
| 회귀 | 골든셋에 민원 케이스 + `required_tools` 채점 추가, 도구 9→10종 라우팅 회귀 측정 | H15-2 R22: 도구 의미 중복이 라우팅을 무너뜨린 선례 |

설비·설비 고장 신고는 별도 경로를 만들지 않는다 — "엘리베이터가 고장났어요" 역시 민원성 질의라 같은 도구가
받고 같은 CTA로 이어진다. 도구 설명에 고장·이상 신고 용례를 명시해 라우팅을 유도한다.

## 대안 (기각)

- **챗 안에서 확인 버튼 → 코드가 `POST /inquiries`**: 규칙 8은 만족하나 SSE 이벤트 계약·챗 UI 확장이 필요하고,
  접수 폼의 검증(제목·본문·분류)을 챗에 복제하게 된다. 딥링크는 기존 폼을 그대로 재사용한다. 기각.
- **접수 전 별도 분류 LLM turn**: 정확도는 오르나 질의당 호출 +1. 파일럿 비용 원칙(규칙 7)에 어긋난다. 기각.
- **민원 임베딩 색인(`inquiries.embedding` + 워커 잡)**: 의미검색 품질은 낫지만 마이그레이션·인제스트 잡·기존 건
  백필이 따라온다. `pg_trgm`으로 먼저 재고, 품질 부족이 실측되면 승격한다(YAGNI). 기각(보류).
- **`is_public` 플래그 신설 후 본문·답변 전문 노출**: 운영 부담(담당자가 건별 공개 승인)과 마이그레이션이 붙는데,
  입주민에게 필요한 정보는 "비슷한 일이 어떻게 처리됐나"라 요약으로 충분. 기각.

## 실측 (2026-08-01 · 로컬 ollama llama3.1:8b · 단발 6질의, 반복 없음)

구현 직후 로컬에서 라우팅을 눈으로 확인한 결과와, 그에 따라 되돌린 초안 결정을 남긴다.
**단발 측정이라 통계적 신뢰도는 없다** — 확정 판정은 골든셋 반복 측정(H17 후속) 몫이다.

| 발견 | 조치 |
|---|---|
| 초안 도구 설명("이전에 접수된 비슷한 **민원**…, 진행 상태만 물으면 get_my_inquiries")이 **정확히 반대로** 갈렸다 — 신고 4건은 전부 `find_in_floor_plan`·문서로 새고, "제가 접수한 민원 처리 어떻게 됐나요"만 이 도구를 골랐다 | 설명 앞머리를 **증상 신고 상황**으로 바꾸고 '민원'·타 도구 이름을 뺐다. `get_my_inquiries`에는 "내가 이미 접수한" 어휘를 명시. 재측정에서 경계 케이스가 2회 연속 정정됐다 |
| 임계 0.3에서 "엘리베이터가 덜컹거려요"에 0.385짜리 "월패드에서 엘리베이터 호출이 안 됩니다"가 근거로 붙자, 모델이 **옳게** 근거로 인정하지 않고 NO_EVIDENCE를 냈다 | 임계 0.3 → **0.5**. trigram은 의미검색이 아니라 어휘 겹침이라 명사 하나로 무관한 사례가 딸려온다. 회수보다 정확도 — 못 찾으면 접수 CTA로 넘어가면 되지만, 엉뚱한 사례는 답변 자체를 폐기시킨다 |
| 카드가 부정문("담당자 답변 기록 없음")으로 끝나면 근거 없음으로 읽힐 소지 | 상태를 긍정문("관리사무소가 처리 중")으로 바꾸고 건수 머리말("비슷한 민원 2건:")을 붙였다. **효과는 단발 측정에서 확인되지 않았다** — 해롭지 않아 유지할 뿐이다 |
| 신고 3건 중 도구 선택 2건, 그중 answered 1건("온수가 미지근해요"). "위층에서 아이들이 뛰어요"는 `find_in_floor_plan`으로 새는 게 재현됐다(평면도 설명에 "소음 신고에 쓰지 않는다"를 명시한 뒤에도) | 8B 라우팅 상한(H15-2 R22·R28과 동형)으로 보고 남긴다. 접수 CTA는 유사 민원 도구가 라우팅된 답변에만 뜬다 — **폴백 경로 CTA는 사용자 지시(2026-08-01)로 제거**했다(답을 못 준 자리에 버튼을 두지 않는다). 따라서 트리아지 라우팅 성공률이 곧 접수 유도율이다 |

**임베딩 승격 조건**: 골든셋 반복 측정에서 트리아지 케이스의 도구 회수율이 낮은 원인이
라우팅이 아니라 `word_similarity` 매칭으로 확인되면, `inquiries` 임베딩 색인으로 승격한다.

## 결과

- 도구 10종. `search_similar_inquiries`가 RESIDENT에게만 노출된다.
- AI가 민원을 만들지 않는다 — 접수 주체는 언제나 사용자다(감사·책임 경로 불변).
- `pg_trgm` extension이 마이그레이션에 추가된다(owner 롤 필요 — compose `migrate` 서비스).
- 8B 라우팅 정확도 회귀는 골든셋으로 감시한다. 악화 시 도구 설명 축소가 1차 대응, 도구 병합이 2차.
